Consolidator — Implementation Plan

Investment wallet consolidator · Spring Boot 3.5.6 / Java 17 / Maven
Phases 0–5

1. Current State Assessment

The application is a scaffold with 5 basic CRUD endpoints (create + list for users, assets, and wallets). The Brapi.dev external API is wired in but only called during wallet creation. Several entities and enums are defined but dead. There are no tests beyond a context-load check, no authentication, and no consolidation logic.

3. Phased Implementation Plan

Phase 0 — Cleanup & Bug Fixes

Housekeeping before adding features. Every item here will cause confusion or defects during later phases if left unfixed.

#TaskWhy
0.1Change BrapiAdapter from @RestController to @ServiceIt has no HTTP endpoints. Misleading annotation.
0.2Make RestTemplate a @Bean in config, inject into BrapiAdapterAvoid creating HTTP client per call; enables mocking in tests.
0.3Resolve fair-value formula: keep Graham (√(22.5 × PE × EPS)), remove PE × EPS from enrichAssetBoth run in sequence; last wins. Pick one.
0.4Remove JPA annotations from UserDTO and WalletDTO recordsThey do nothing on records — belong on entities only.
0.5Create response DTOs without password; update controllers to use themPassword hash currently leaks in every user response (security).
0.6Remove @RequestParam from service-layer method signaturesSpring MVC annotation has no effect in @Service beans.
0.7Rename createAdmin → createUser / createWalletMisleading — creates a regular user/wallet, not an admin.
0.8Add @AllArgsConstructor to WalletConsistency across entities.
0.9Remove dead imports, commented-out blocks, unused variablesReduce noise.

Phase 1 — JWT Authentication

Users can register but cannot log in. Add a full JWT auth flow so that endpoints can be protected.

Dependency: io.jsonwebtoken:jjwt-api:0.12.6 + runtime jars

#TaskDetails
1.1Add jjwt dependency to pom.xmlapi, impl, jackson — all 0.12.6
1.2Create security/ packageMove security classes here.
1.3Create JwtServicegenerateToken(), extractUsername(), isTokenValid(). Reads app.jwt.secret.
1.4Create JwtAuthFilterExtract Bearer token, validate, set SecurityContext.
1.5Create UserDetailsServiceImplLoad user from DB by email.
1.6Create AuthController (POST /auth/login)Accept email+password, return JWT token.
1.7Create LoginRequestDTO / LoginResponseDTORequest: email, password. Response: token.
1.8Add config to application.propertiesapp.jwt.secret, app.jwt.expiration
1.9Update SecurityConfigPermit /auth/login + /h2-console/**. Protect everything else. Register JWT filter.

2.2 Asset Update Rules on Transaction

OperationAsset Field Updates
BUY amount += tx.amount
mediumPrice = weighted avg(old, new)
totalInvested = mediumPrice × amount
SELL amount -= tx.amount
totalInvested = mediumPrice × amount (proportional cost basis)

2.3 Enable Enum Fields

  • Uncomment TransactionType type in Transaction.java — wire to DTO
  • Uncomment AssetType type in Asset.java — add to AssetDTO

Phase 3 — Portfolio Consolidation

The core feature: a single endpoint returning a fully calculated portfolio summary for a wallet — live prices, allocation, and P&L.

#TaskDetails
3.1 Create PortfolioSummaryDTO Nested records: wallet-level totals + per-asset breakdown with currentPrice, mediumPrice, totalInvested, profitLoss, allocation%.
3.2 Create ConsolidationService Load wallet + assets, fetch live prices from Brapi (per-request cache to avoid N+1), compute metrics, handle failed tickers gracefully.
3.3 Create consolidation endpoint GET /wallet/{walletId}/summary
3.4 Graceful Brapi degradation Failed ticker → include asset with currentValue = null + warning flag. Don't fail the whole request.
